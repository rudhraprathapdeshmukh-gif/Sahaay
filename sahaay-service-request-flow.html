Sahaay Service Request Flow

Platform-directed matching between customers and verified service providers

Overview

Sahaay is a hyperlocal service platform connecting customers with verified home service providers (electricians, plumbers, carpenters, etc.). The platform uses real-time GPS matching and a broadcast-based request system.

✅ Fixed Issue: Service providers can now see incoming customer requests in the "Incoming Requests" section on their homepage

How It Works

1

Customer Submits Request

Customer fills out service request form → Request saved with status: 'broadcast' and provider_id: null

// Request creation const booking = await requestService({ customer_id: user.id, provider_id: null, // Unassigned pool service_id: serviceId, status: 'broadcast', address: address, notes: description, amount: calculatedPrice });
2

Request Broadcast to Nearby Providers

Real-time Supabase subscription notifies providers within 10km radius who offer matching service category

// Provider dashboard subscription supabase.channel('provider-broadcast-requests') .on('postgres_changes', { event: '*', schema: 'public', table: 'bookings', filter: 'status=eq.broadcast' }) .subscribe();
3

Provider Views Incoming Requests

Requests appear in "Incoming Requests" section on provider homepage with customer details, location, and estimated price

// Fetch incoming requests const incomingRequests = bookings.filter(b => b.status === 'broadcast' && b.provider_id === null && b.service_id === provider.service_id );
4

Provider Accepts/Declines

Provider clicks "Accept Job" (atomic transaction) or "Decline" (stays in pool for other providers)

// Atomic acceptance prevents race conditions const acceptRequest = async (bookingId, providerId) => { // Only update if still broadcast and unassigned return supabase.from('bookings') .update({ provider_id: providerId, status: 'confirmed' }) .eq('id', bookingId) .eq('status', 'broadcast') .is('provider_id', null); };

Technical Architecture

Key Components

  • Frontend: React + TypeScript + Vite
  • Backend: Supabase (PostgreSQL + Realtime)
  • Authentication: Supabase Auth with role-based access
  • Real-time: Postgres Change Data Capture
  • Styling: TailwindCSS + custom design system
  • Maps: GPS location services for proximity matching

Database Schema
