Booking Rules Overview

  • ✓
    Maximum 2 active services per customer
    A customer can have at most 2 active bookings (pending, confirmed, or in_progress status) at any time.
  • ✓
    Prevention of 3rd service
    When 2 services are active, booking a 3rd service is blocked in both frontend and database.
  • ✓
    Service release after completion
    Customer can start another service only after one of the previous 2 is completed or cancelled.

  • ✓

Database Trigger Function

CREATE OR REPLACE FUNCTION check_customer_active_bookings_limit()
RETURNS TRIGGER AS $$
DECLARE
  active_count INTEGER;
BEGIN
  SELECT count(*) INTO active_count
  FROM bookings
  WHERE customer_id = NEW.customer_id
    AND status IN ('pending', 'confirmed', 'in_progress');

  IF active_count >= 2 THEN
    RAISE EXCEPTION 'Customer has reached the maximum limit of 2 active services.';
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

User Flow

1 Customer visits Find Providers page

Active bookings count is fetched and displayed in an info banner showing "You have X active booking(s) (max 2 allowed)."

2 Browse available providers

Each provider card displays "Starting from ₹199" and a "Book Now" button (or "Limit Reached" if at 2 active bookings).

3 Attempt to book when at limit

If customer already has 2 active bookings, the "Book Now" button is replaced with a disabled "Limit Reached" button with tooltip.

4 Frontend validation

If user somehow bypasses UI, the requestService() function checks the count and throws an error.

5 Backend validation

Database trigger performs final validation before INSERT. If limit exceeded, transaction is rolled back with clear error message.

6 After booking completion

When a booking status changes to "completed" or "cancelled", the active count decreases and customer can book again.

Real-Time Features

Supabase Realtime Subscriptions

  • Active count updates automatically when bookings change
  • Provider availability refreshes every 15 seconds + on database changes
  • No manual refresh needed for customers
  • UI stays in sync with database state

Subscription Code

useEffect(() => {
  if (!user?.id) return
  let cancelled = false

  const fetchCount = async () => {
    const n = await fetchCustomerActiveBookingsCount(user.id)
    if (!cancelled) setActiveCount(n)
  }

  fetchCount()

  const channel = supabase
    .channel(`active-count-${user.id}`)
    .on('postgres_changes', {
      event: '*',
      schema: 'public',
      table: 'bookings',
      filter: `customer_id=eq.${user.id}`
    }, () => fetchCount())
    .subscribe()

  return () => {
    cancelled = true
    supabase.removeChannel(channel)
  }
}, [user?.id])
