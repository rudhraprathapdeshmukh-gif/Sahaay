Sahaay Service Request Flow

Complete implementation of platform-directed service matching with pool-based provider assignment

Live & Ready

Core Architecture

🔧

Pool-Based Matching

Customers cannot select specific providers. All requests go to provider pool with provider_id: null, maintaining platform control over assignment.

📍

Auto-Location Detection

GPS coordinates automatically captured on request submission. No manual address entry required from customers.

📅

Time Constraints

Requests limited to 1 week in advance. Maximum 2 active requests per customer to prevent abuse.

Customer Flow

1. Homepage CTA

Authenticated customers see "Request Service Now" button. Shows active request count and disables at limit.

2. Service Selection Wizard

Category → Service → Duration → Problem description → Date/Time → Auto-location → Submit

3. Provider Matching

Requests shown to providers within 20km radius matching service type. Providers "claim" requests from pool.

4. Request Management

Customers can view bookings, see status, and delete pending/unassigned requests. Providers can claim, complete, or review.
