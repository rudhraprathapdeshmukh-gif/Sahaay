Architectural Model

Unassigned Booking Pool Model:

  • Customers create requests with provider_id: null
  • Providers search/claim from the unassigned pool
  • Geolocation filters providers within 10-20km radius
  • Service type matching ensures relevance
  • Real-time subscriptions update all parties
Booking Creation Logic
// All requests created with provider_id: null (pool-based)
const requestService = async (
  customerId: string,
  serviceId: number,
  scheduledAt: string,
  notes: string,
  address: string,
  latitude: number,
  longitude: number
) => {
  const { data, error } = await supabase
    .from('bookings')
    .insert({
      customer_id: customerId,
      service_id: serviceId,
      scheduled_at: scheduledAt,
      notes: notes,
      address: address,
      latitude: latitude,
      longitude: longitude,
      status: 'pending',
      provider_id: null  // CRITICAL: Always null
    })
    .select()
}

Real-Time Implementation

Supabase Real-Time Subscriptions:

Provider-Side Real-Time
// Providers see new unassigned requests in real-time
const channel = supabase.channel('unassigned-bookings')
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'bookings',
    filter: 'provider_id=is.null'  // Only unassigned
  }, (payload) => {
    // Add to provider's view of available requests
    setAvailableRequests(prev => [payload.new, ...prev])
  })
  .subscribe()
Customer Booking Status
// Customers see when providers claim their requests
const channel = supabase.channel(`customer-bookings-${userId}`)
  .on('postgres_changes', {
    event: 'UPDATE',
    schema: 'public',
    table: 'bookings',
    filter: `customer_id=eq.${userId}`
  }, (payload) => {
    if (payload.new.provider_id) {
      // A provider claimed this request
      showNotification('Request claimed by provider!')
    }
  })
  .subscribe()
